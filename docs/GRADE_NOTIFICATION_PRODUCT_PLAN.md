# 학년 관리 및 공지 알림 기획서

- 작성일: 2026-09-18
- 상태: 1단계·2단계 구현 완료, 배포 전 (2026-09-18)
- 구현 메모: 학년 필터는 `ysync.notification.grade-filter.enabled`(기본 false)로 전환합니다. 2단계 전환은 이 설정만 켜면 되고, 되돌리면 기존 발송 방식으로 복구됩니다. 학년도 기준일은 `ysync.academic-year.cutover-month/day`로 조정합니다.
- 대상: 학과 내부 Y-Sync 사용자
- 범위: 학생의 학년 선택·갱신과 공지 푸시·앱 알림함 수신 대상

## 1. 목표

학생이 자신의 현재 학년을 직접 선택하고, 전체 공지와 해당 학년 공지만 알림으로 받는다. 관리자는 모든 학생의 학년을 매번 관리하지 않고 예외 상황만 지원한다.

학번으로 현재 학년을 추정하거나 매년 자동 진급시키지 않는다. 휴학·복학·유급 등으로 입학 연도와 실제 학년이 다를 수 있기 때문이다.

## 2. 현재 상태와 변경 범위

현재 공지에는 대상 학년이 있지만 회원 정보에는 현재 학년이 없다. 공지 푸시와 앱 알림함은 활성 회원·공지 알림 수신 동의만 확인하며 학년별로 구분하지 않는다.

이번 기획에서 추가할 기능:

1. 가입할 때 학년 또는 전체 공지만 받기 선택
2. 기존 회원의 첫 학년 설정
3. 새 학년도 첫 사용 시 재확인
4. 내 정보에서 언제든 변경
5. 푸시와 앱 알림함의 수신 조건 통일

공지 열람 권한, 관리자 권한, 댓글 알림, 공지 수정 시 재발송 정책은 변경하지 않는다. 다른 학년 공지도 기존처럼 직접 찾아 읽을 수 있다.

## 3. 사용자 선택값

사용자에게 다음 네 가지 선택지를 제공한다.

- 1학년
- 2학년
- 3학년
- 전체 공지만 받기

‘전체 공지만 받기’는 모든 학년 공지를 받는다는 뜻이 아니다. 공지 대상이 ‘전체’인 공지만 받는다는 뜻이다. 졸업·휴학 등 신분을 별도로 수집하지 않고도 학년 공지 수신을 중단할 수 있다.

처음부터 아무것도 선택하지 않은 ‘미설정’은 시스템 상태다. 사용자가 명시적으로 선택한 ‘전체 공지만 받기’와 구분한다.

## 4. 가입 흐름

가입 화면에 학년 선택을 추가한다. 설명은 다음처럼 표시한다.

> 전체 공지와 선택한 학년의 공지 알림을 받습니다. 나중에 내 정보에서 변경할 수 있습니다.

새 클라이언트의 가입 화면에서는 네 가지 중 하나를 선택해야 완료할 수 있다. 서버는 가입이 성공한 시점에 선택값과 현재 학년도를 함께 저장한다. 가입 실패 시 확인 완료 상태를 남기지 않는다.

일반 가입 외 기존 소셜 가입·가입 완료 경로에도 같은 규칙을 적용한다. 관리자 사전 등록이나 이전 버전 클라이언트에서 학년 없이 생성된 계정은 미설정으로 두고, 새 앱 사용 시 설정을 안내한다. 기존 클라이언트를 깨뜨리지 않도록 최초 도입 시 API의 새 필드는 선택적으로 받는다.

## 5. 기존 회원의 첫 설정

로그인 후 또는 이미 로그인된 앱을 다시 사용할 때 학년 설정 상태를 확인한다.

미설정 회원에게는 다음 안내를 보여준다.

> 공지 알림을 받을 학년을 선택해 주세요.

네 가지 선택지와 ‘저장’, ‘나중에’ 버튼을 제공한다. 미설정 상태에서는 전체 공지만 받는다.

‘나중에’를 선택해도 앱 사용을 막지 않는다. 같은 사용 세션에서 안내를 반복하지 않고, 다음 앱 실행 또는 로그인 시 다시 안내한다. 내 정보에는 설정이 필요하다는 표시를 유지한다.

## 6. 학년도 계산

**정책 기준은 매년 3월 1일 00:00, Asia/Seoul이다.** 학교 정책이 다른 경우 출시 전에 기준일을 변경한다.

- 3월부터 12월: 현재 연도가 학년도
- 1월과 2월: 이전 연도가 학년도

예시:

| 날짜 | 현재 학년도 |
|---|---|
| 2027-02-28 | 2026 |
| 2027-03-01 | 2027 |
| 2027-09-01 | 2027 |

학기와 학년도를 구분한다. 2학기 시작만으로 학년을 올리거나 재확인을 요구하지 않는다. 휴대폰 날짜가 잘못되어 있어도 결과가 달라지지 않도록 서버가 계산한다.

## 7. 학년 갱신 흐름

서버가 다음 중 하나를 만족하면 확인이 필요하다고 응답한다.

- 학년 수신 선택이 미설정
- 확인한 학년도가 없음
- 마지막 확인 학년도가 현재 학년도보다 이전

새 학년도에 첫 사용 시 다음 안내를 표시한다.

> 올해 현재 학년을 확인해 주세요.
> 이전 선택: 1학년

자동으로 다음 학년을 선택하거나 저장하지 않는다. 이전 값을 참고로 보여주고 학생이 현재 상태를 명시적으로 확인한다. 같은 학년을 다시 선택해도 정상 처리하며 확인 학년도만 최신으로 갱신한다.

‘전체 공지만 받기’를 선택한 회원도 새 학년도에 재확인한다. 다시 재학 중이거나 학년 공지 수신이 필요해졌을 수 있기 때문이다.

### 예시

1. 2026년 9월 가입하며 1학년 선택 → 1학년, 확인 학년도 2026 저장
2. 2027년 2월 접속 → 안내 없음
3. 2027년 3월 접속 → 확인 안내
4. 2학년 선택 → 2학년, 확인 학년도 2027 저장
5. 이후 접속 → 해당 학년도에는 재안내하지 않음
6. 휴학·유급 등으로 1학년을 유지한다면 1학년을 다시 선택 → 확인 완료

## 8. 안내 시점과 실패 처리

- 로그인 완료 후 회원 정보 조회 시 확인
- 앱을 다시 실행하거나 백그라운드에서 돌아올 때 회원 정보 갱신으로 확인
- 매년 전 회원을 수정하는 예약 작업은 만들지 않음
- 페이지를 이동할 때마다 요청하거나 팝업을 띄우지 않음
- 이미 같은 세션에서 안내했다면 반복 표시하지 않음. 단, 학년도가 바뀌면 새 안내 대상
- 저장 요청 중 중복 제출 방지
- 저장 실패 시 기존 선택과 확인 학년도를 유지하고 재시도 안내
- 네트워크 연결이 없으면 확인 불가로 처리하고 앱 사용은 유지. 통신 복구 후 재확인

선택창을 2월에 열고 3월에 저장하더라도 서버의 저장 시점 학년도를 기록한다.

## 9. 확인 전 알림 정책

| 회원 상태 | 발송 기준 |
|---|---|
| 학년 미설정 | 전체 공지만 |
| 이전에 선택한 학년이 있으나 올해 미확인 | 기존 학년 + 전체 공지 |
| 올해 학년 확인 완료 | 선택 학년 + 전체 공지 |
| 전체 공지만 받기 선택 | 전체 공지만 |
| 공지 알림 끔 | 공지 푸시·앱 알림함 모두 생성하지 않음 |
| 비활성 계정 | 공지 알림 대상에서 제외 |

올해 확인하지 않았다는 이유로 기존 학년 알림을 갑자기 끊지 않는다. 대신 오래 접속하지 않으면 이전 학년의 알림을 받을 수 있다는 한계를 수용한다.

학년 선택 변경은 서버 저장 완료 후 새로 수신자를 선정하는 공지부터 반영한다. 이미 발송 중인 공지를 회수하거나 과거 알림을 삭제하지 않는다. 소급 발송도 하지 않는다.

## 10. 푸시와 앱 알림함 발송 규칙

공지 저장 트랜잭션이 성공한 뒤 기존 비동기 발송 흐름에서 수신자를 한 번 선정한다.

대상 조건:

1. 활성 회원
2. 공지 알림 수신 동의
3. 전체 공지이거나 회원의 선택 학년과 공지 대상 학년이 일치

같은 수신자 목록으로 앱 알림함 저장과 푸시 대상을 결정한다. 푸시 토큰이 없는 회원도 앱 알림함에는 저장한다. 푸시 전송 실패가 앱 알림함 저장을 되돌리지 않도록 기존 독립 처리를 유지한다.

| 공지 대상 | 1학년 선택 | 2학년 선택 | 3학년 선택 | 전체 공지만 | 미설정 |
|---|---|---|---|---|---|
| 전체 | 수신 | 수신 | 수신 | 수신 | 수신 |
| 1학년 | 수신 | 제외 | 제외 | 제외 | 제외 |
| 2학년 | 제외 | 수신 | 제외 | 제외 | 제외 |
| 3학년 | 제외 | 제외 | 수신 | 제외 | 제외 |

표는 활성 상태이고 공지 알림을 켠 회원 기준이다. 관리자도 동일한 선택 규칙을 적용한다. 관리자라고 모든 학년 알림을 자동 수신하는 예외는 만들지 않는다.

## 11. 내 정보와 관리자 지원

### 학생

내 정보에 다음을 표시한다.

- 공지 알림 대상: 1학년 / 2학년 / 3학년 / 전체 공지만 / 미설정
- 확인 학년도
- ‘알림 대상 변경’ 버튼
- 미설정 또는 학년도 갱신이 필요하면 안내 표시

회원이 내 정보에서 변경·확인하면 서버가 현재 학년도로 확인 상태를 갱신한다. 공지 알림을 켜고 끄는 기존 설정과는 별개다. 학년을 바꿔도 꺼둔 알림을 자동으로 켜지 않는다.

### 관리자

회원 관리에서 선택값과 미확인 여부를 조회하고, 문의 시 예외적으로 수정할 수 있다. 수정 권한은 기존 회원 수정 권한을 따른다. 관리자 수정도 현재 학년도 확인으로 처리한다.

전 회원의 학년을 매년 일괄 입력하거나 학번으로 강제 진급시키는 작업은 요구하지 않는다. CSV 학년 열·일괄 학년 변경 기능은 초기 범위에서 제외한다.

## 12. 데이터 및 API 설계 원칙

### 회원 데이터

| 필드 개념 | 값 | 의미 |
|---|---|---|
| 학년 수신 선택 | 미설정 / GRADE_1 / GRADE_2 / GRADE_3 / GENERAL_ONLY | 현재 알림 대상 선택 |
| 확인 학년도 | 정수 또는 없음 | 서버가 계산한 마지막 확인 학년도 |

공지의 ALL과 회원의 GENERAL_ONLY를 분리한다. ‘전체 공지를 받기’와 ‘모든 학년 공지를 받기’를 혼동하지 않기 위해서다. 미설정은 null로 표현할 수 있으나 확정 선택값과 명확히 구분한다.

### API 동작

- 가입: 선택값을 추가로 수신. 확인 학년도는 클라이언트가 지정하지 않음
- 본인 정보 조회: 선택값, 확인 학년도, 서버 현재 학년도, 재확인 필요 여부 반환
- 본인 선택 수정: 허용된 네 값만 수신하고 인증된 본인 정보를 수정
- 관리자 수정: 기존 관리자 권한·대상 계정 보호 규칙 적용
- 수정 요청에서 학번이나 타인 회원 ID만 바꿔 다른 사람의 학년을 수정할 수 없어야 함
- 학년 선택과 확인 학년도는 한 트랜잭션으로 저장

정확한 URL과 DTO 명칭은 구현 시 기존 API 명명 규칙에 맞춘다. 이 문서는 동작 계약을 정의하며 구현 코드를 포함하지 않는다.

## 13. 도입 및 배포 계획

### 1단계: 선택·갱신 기능 도입

- 회원 데이터에 새 필드 추가. 기존 회원은 미설정
- 가입·기존 회원 안내·내 정보·학년도 확인 기능 구현
- 관리자 예외 수정 지원
- 이 단계에서는 현재 알림 발송 범위를 유지
- 학년 미설정 회원 수를 확인해 전환 준비 상태 판단

### 2단계: 학년별 알림 적용

- 학생들에게 선택 기능을 안내하고 운영자가 전환 시점 결정
- 남은 미설정 회원은 전체 공지만 받는다는 정책을 명확히 안내
- 푸시와 앱 알림함에 공통 수신자 선정 적용
- 전체·학년 공지를 각각 검증한 뒤 운영 확인

회원 전원이 입력할 때까지 무기한 기다릴 필요는 없다. 미설정 회원의 학년 알림이 중단되는 영향을 알고 전환해야 한다.

### 복구

문제가 발생하면 학년 필터 적용을 되돌려 기존 발송 방식으로 복구할 수 있도록 코드 변경을 단계별로 분리한다. 추가된 회원 학년 데이터는 보존한다. 이전 버전과의 호환을 위해 최초 필드는 nullable로 도입하며 실제 DB 변경 전 백업·스키마 확인을 수행한다.

## 14. 검증 및 완료 기준

### 학년도·갱신

- 한국 시간 2월 말 마지막 순간과 3월 1일 경계에서 학년도가 정확함
- 윤년 2월 29일도 같은 규칙 적용
- 2학기 시작에는 재확인하지 않음
- 같은 학년 재선택·전체 공지만 재선택도 확인 완료 처리
- 나중에 선택 시 같은 세션에서 반복 안내하지 않음
- 새 학년도 또는 다음 앱 실행에서 필요한 안내가 다시 나타남
- 서버 저장 실패 시 기존 설정 유지
- 본인이 아닌 회원의 설정 수정 불가

### 알림

- 1·2·3학년 및 전체 공지의 대상이 수신 표와 일치
- 미설정·전체 공지만·학년도 미확인 상태가 정책대로 처리됨
- 비활성 계정·공지 알림 미동의 제외
- 토큰 없는 대상은 앱 알림함만 생성
- 관리자도 학년 규칙 적용
- 학년 변경 후 새 공지부터 적용하고 과거 알림은 유지
- 푸시·앱 알림함의 학년 판정이 같음
- 푸시 실패가 앱 알림함 저장을 취소하지 않음

### 호환성

- 기존 회원과 학년 필드 없는 이전 가입 요청을 처리할 수 있음
- 기존 댓글 알림·공지 열람·권한에 변화 없음
- 기존 공지 알림 OFF 상태를 유지

## 15. 한계와 제외 범위

학생의 자기 신고를 사용하므로 잘못된 학년 선택을 기술적으로 완전히 막지는 않는다. 학년 정보는 알림 분류에만 쓰며 비공개 자료 접근이나 관리자 권한을 부여하는 근거로 쓰지 않는다.

오랫동안 접속하지 않는 학생은 기존 학년 기준 알림을 받을 수 있다. 학적 시스템 연동, 자동 진급, 휴복학·졸업 상태 관리, 관리자 전체 명단 정리, 별도 갱신 독촉 푸시, 과거 알림 재분류는 이번 범위에 포함하지 않는다.

학교의 학년도 기준일이 3월 1일과 다른 경우 출시 전에 조정한다. 테스트로 발송 대상은 검증할 수 있지만 실제 푸시 도착은 기기의 권한·토큰·FCM 상태에 따라 달라진다.
